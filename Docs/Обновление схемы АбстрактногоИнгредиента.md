# План обновления схемы AbstractIngredient

## Цель
Дополнить текущую схему AbstractIngredient новыми полями, сохраняя обратную совместимость.

## Новые поля верхнего уровня

| Поле | Тип | Описание |
|---|---|---|
| `ingredient_type` | enum | product / dish / preparation / abstract / spice / drink |
| `name_variants` | object | {ru, ru_with_yo, en, it, origin} |
| `russian_traditional_name` | строка | Устоявшийся русский термин (напр. «Рожки» для Киффери Ригате) |
| `origin_country` | строка | Страна происхождения |
| `origin_region` | строка | Регион происхождения |
| `aliases` | массив | Дополнительные алиасы для поиска |

## Новые поля внутри semantic_data

| Поле | Тип | Описание |
|---|---|---|
| `pairings.wines` | массив | Сочетаемость с винами |
| `pairings.drinks` | массив | Сочетаемость с напитками |
| `varieties` | массив объектов | Разновидности и подвиды |
| `fillings` | массив объектов | Типы начинки |
| `serving_methods` | массив | Способы подачи |
| `classification` | строка | Классификационная группа (напр. «pasta ripiena») |

## Новые HTML-блоки в description (опциональные)
- «Виды и формы»
- «Традиционная начинка»
- «Приготовление»
- «Способы подачи»
- «История и происхождение»
- «Отличия от похожих продуктов»

## Правила оформления (сохраняются)
1. `name` — без Ё
2. `synonyms` — с Ё-вариантами
3. `name_normalized` — транслит
4. `description` — HTML с блоками
5. `category` — из иерархии Скурихина
6. `semantic_data` — с пробелами, не snake_case
7. `tags` — с пробелами, нижний регистр
8. Citation — ❌ никогда
9. Нутриенты — только по запросу
10. Иностранные названия — «Русская транскрипция (Оригинал)»
