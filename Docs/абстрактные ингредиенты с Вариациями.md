## 10. Подход к вариациям продукта (без дублирования)

### Принцип
Базовая карточка (например, «Творог» 5% классический) — это дефолт. Все остальные вариации — отдельные `AbstractIngredient` со своими КБЖУ, но связанные с базовой через **семантические теги**, а не через новое поле `base_ingredient`.

### Семантические теги для вариаций

| Тип вариации | Тег (`tag_type`) | Примеры значений |
|---|---|---|
| Жирность | `fat_content` | обезжиренный (до 0,5%), низкожирный (2–4,5%), стандартный (5–9%), жирный (10%+) |
| Консистенция/тип | `consistency` / `type` | классический, мягкий, зерненый, пластовой |
| Обработка | `processing` | пастеризованный, стерилизованный |

### Сценарии замены в рецепте (через `RecipeFoodItem`)

1. **Оставить базовый** — Хозяйка ничего не меняет, КБЖУ из базовой карточки.
2. **Заменить на другой абстрактный** — через `RecipeIngredientOption.alternative_ingredient` или `IngredientSubstitutionRule` с `substitution_type='exact'`.
3. **Заменить на брендовый** — через `RecipeFoodItem.branded_ingredient` или `RecipeIngredientOption.alternative_branded` (модель `BrandedIngredient` уже есть).
4. **Заменить на полуфабрикат/рецепт** — через `RecipeFoodItem.subrecipe` (Recipe с `recipe_type='semi_finished'`).

### Автоподбор замен по тегам
`IngredientSubstitutionRule` с `substitution_type='tag_based'` и тегами `required_tags` / `optional_tags` / `forbidden_tags` — уже реализовано в модели.

### Итог
Новых полей в `AbstractIngredient` не добавляем. Всё делается через:
- семантические теги,
- `BrandedIngredient`,
- `Recipe` (полуфабрикаты),
- `RecipeIngredientOption`,
- `IngredientSubstitutionRule`.
